# v0.1.9 — 控制台选择 Xray 版本

## 改动

- `x-ui` 新增「9. 切换 Xray 内核版本」，按序号选择官方版本，标记当前版本和预发布版本，不要求填写版本号。
- 与当前 Angelo 3x-ui 一样读取 XTLS/Xray-core 默认一页 Releases，使用 v26.6.27 最低版本规则，并按本机 Linux 架构过滤。
- 下载、官方 SHA256 校验完成后才停止服务；顺序校验新内核和现有配置，避免在小内存节点同时运行两份内核。
- 切换失败时恢复旧可执行文件和原运行状态；不恢复旧状态快照，不覆盖用户、配置、Token、GUID 或累计流量。
- 内核切换与节点更新共用文件锁。升级、降级均可选；原本停止的服务保持停止。
- 自动切换仅支持标准安装路径；服务不存在、状态查询失败或 systemd 启动配置不匹配时拒绝替换。回滚无法确认服务停止时保留备份并报告错误。
- 正式发布流程必须先通过现有 Linux CI 验证。

## 验证状态（2026-11-10）

- Windows/Go 1.26.0：`go test ./...`、`go vet ./...` 通过；默认真实 Xray 集成测试因未设置 XRAY_BINARY 而跳过。
- 新增测试覆盖版本筛选、序号选择/取消、HTTP 错误、SHA256 与 .dgst 校验、错误下载地址、压缩包重复文件/符号链接，以及配置校验/启动/健康检查/停止失败后的回滚和数据保留。
- Linux amd64、arm64、386、armv7 交叉编译与打包通过；这是构建验证，不是这些架构的运行验证。
- 另行下载并校验官方 Windows Xray v26.10.31 后尝试真实流量集成：本机回环 gRPC 请求收到 AdGuard HTTP 502 拦截页面，未通过。未为绕过此问题修改系统或客户端设置；Linux CI 结果才可作为发布验证依据。
- 独立复审已通过，服务状态误判问题已修复；Linux 实际内核流量、安装/升级保留、64/128 MiB cgroup 仍待完成。发布前必须补齐，不将旧版本报告当成本次通过记录。

## 使用

已安装节点在正式发布后运行 `angelo-node-update v0.1.9`，再运行 `sudo x-ui` 选择第 9 项。首次安装使用 release 中的 install.sh。切换 Xray 会短暂断开连接。
