# 主面板可选补丁：按节点本地 ID 重置入站流量

适用基线：`AngeloSakura/Angelo-xui-plugin-2` 的 `bb0bf320301fb03d1975ff1489e36f13324f15d7`（3.7.0）。

原主面板的 `Remote.ResetInboundTraffic` 把主面板数据库里的入站 ID 发给节点。当主面板 ID 是 7、节点同一标签的入站 ID 是 42 时，原请求会重置节点的 7 号入站，或者报不存在。本补丁先调用已有的 `resolveRemoteID(ctx, ib.Tag)`，再请求节点的 42 号入站；查不到标签时直接报错。

补丁只修改主面板一处 Go 函数，没有 SQL、数据库迁移、初始化用户、配置重置或密钥更换步骤。节点正常连接和倍率同步无需此补丁；使用「重置指定入站流量」时建议安装。

## 应用和验证

在主面板源码仓库根目录执行；把路径换成该补丁的实际位置：

```sh
git apply --check /path/to/master-reset-inbound-remote-id.patch
git apply /path/to/master-reset-inbound-remote-id.patch
gofmt -w internal/web/runtime/remote.go
go test ./internal/web/runtime
```

`git apply --check` 失败时先检查当前版本是否已经修复，或函数是否被其他改动修改；不要强制覆盖源码。原仓库的 Go 工具链和构建依赖应保持其自身要求。

之后按主面板独立升级流程部署编译好的主面板程序：升级前停止主面板并备份原数据库和配置，只替换主面板程序，再启动原服务。不要运行首次安装/初始化命令，也不要把轻量节点程序覆盖到主面板。升级方式及回滚流程以仓库的主面板更新文档为准。

验收至少覆盖：主面板与节点的入站 ID 不同；节点上恰好存在一个与主面板 ID 同号、但标签不同的入站；重置后只有目标标签对应的节点入站清零，另一入站及所有客户端累计流量保留。再验证找不到标签时不发送重置请求。

本补丁文件已按上述基线检查上下文；主面板完整编译/测试与数据库保留验证应在主面板发布门禁中完成。
